# A1：SPAN52层级特征选择方案 v0.1

2026-10-12。状态：讨论稿。既有`research/modules/candidates.py`中FusionGate已实现下述适配；本次不改模型、训练配置或队列，不启动训练。

## 原文机制与适配边界

SSIU作者稿III-F、式19–20：三个层级专家，每个经过1×1卷积产生logits，专家轴softmax后将三个输入加权求和，再使用`S+Conv1×1(S)`输出。来源：https://arxiv.org/html/2506.11823v1。

本方案借鉴其“层级作为专家、输入相关softmax选择”机制，使用SPAN原四路，先加权，再保留concat和原conv_cat。正式命名建议`SPAN52-FusionGate4`或“MoE-FS启发的四路融合”，不声称直接复现SSIU原模块。不是稀疏top-k MoE；四路均计算。

当前论文原码固定commit在线读取失败；本次原机制依据论文公式和本地历史源码审计，未重新完成官方代码逐行复核。

## 原结构与位置

RGB输入X N×3×H×W；保持原模型的减均值/乘img_range处理。conv_1得到F0。6个SPAB串联产生B1…B6，conv_2处理B6得到F6；同时取block6第一卷积的返回特征T6。

**T6不是block5输出，也不是block6最终输出**；源代码out1经inplace SiLU后返回，故应以实际返回张量为准，不解释成未激活的裸卷积值。

原融合：`Y = conv_cat(cat(F0,F6,B1,T6))`。
拟议融合：`Y = conv_cat(cat(G0*F0,G1*F6,G2*B1,G3*T6))`。

门控仅位于conv_cat前：F6已经过conv_2；不放在PixelShuffle之后，不改SPAB门控，不额外加输入残差。

## 尺寸/接口表

|节点|一般尺寸|LR64×64训练样例|
|---|---|---|
|输入RGB|N×3×H×W|N×3×64×64|
|F0/F6/B1/T6每路|N×52×H×W|N×52×64×64|
|每路1×1 logits|N×52×H×W|N×52×64×64|
|stack logits/weights|4×N×52×H×W|4×N×52×64×64|
|concat加权特征|N×208×H×W|N×208×64×64|
|原conv_cat输出|N×52×H×W|N×52×64×64|
|原上采样卷积输出|N×48×H×W|N×48×64×64|
|PixelShuffle×4输出|N×3×4H×4W|N×3×256×256|

四路保留原顺序，共享LR像素网格；1×1 stride1，无resize/token重排/窗口padding。NCHW、dtype、device继承原特征。logits无固定范围，softmax权重[0,1]，门控(0,4)且每像素/通道四路和为4（有限精度极端可逼近边界）。特征仍有符号，不clamp、不额外归一化、不假定四路统计相同。

softmax只沿stack第0维专家轴，不沿batch/通道/空间轴。不使用squeeze。无跨图片缓存、EMA或新buffer。门控和主干都接最终loss，新增参数必须进入optimizer。任意H/W合法；批次内拼接仍要求同图像尺寸，工程验证覆盖N=1/2、奇数非方形。

## 融合公式与初始化

`Li = Wi Fi + bi`，每路独立52→52的1×1。
`Ai = softmax_expert(L)i`；`Gi = 4 Ai`；`Zi = Gi Fi`。
`Y = P(concat(Z0,Z1,Z2,Z3))`，P为原conv_cat。

所有门控Wi/bi为0时，Ai=1/4、Gi=1，恢复原concat映射。直接用Ai会缩小原特征幅值，故乘4。门控输出直接乘输入，不是乘以零初始化的新残差scale；零logits不会在结构上阻断门控参数学习。全部专家加相同logit存在softmax不辨识方向，但不表示所有可用梯度为零。

本方案改变了原特征到融合层的梯度路径；初始化映射相同仅用于减少起点差异，不保证之后PSNR不下降。极端门控可能压制部分专家并接近4倍放大其他专家，需记录分布与幅值。

## 参数和计算

每个门控1×1含bias：52×52+52=2756；四路新增11024。conv_cat保持208→52，已有参数10868，不重复计新增。

|参数口径|SPAN52|FusionGate4|差值|
|---|---:|---:|---:|
|合并部署参数|498208|509232|11024，+2.2127%|
|训练可学习参数|2157136|2168160|11024|
|模型Parameter元素总量（含冻结eval_conv，不含buffer）|2621964|2632988|11024|

部署时门控随输入变化，不能像Conv3XC一样折叠为固定卷积。上述为当前代码构造计数；实际延迟/显存未测。

新增门控卷积MAC=batch×4×52²×H×W。N1/LR64为44,302,336 MAC；2 FLOPs/MAC口径为88,604,672卷积FLOPs。未计softmax、bias加法、乘法、stack/concat和访存，不称完整FLOPs。

单个4路FP32张量为4N52HW×4字节；N1/LR64为3.25 MiB；N1/LR180×320为45.70 MiB。训练还需保存其他激活与梯度，不能当成peak显存增量。不得仅凭2.21%参数增长推断2.21%延迟增长。

|方案|改变|新增部署参数|取舍|

|仅逐像素标量门控|四个52→1卷积，权重跨通道共享|212|更便宜，但选择粒度变粗，不与原稿主方案混为同一次实验|

## 测试前讨论清单

建议第一项锁定：四路原位置、逐像素逐通道门控、独立1×1、专家softmax×4、零logits初始化、保留原conv_cat；只测试A1，不叠其他候选。是否目标是原文忠实移植还是保留SPAN结构的最小适配，需要在训练前明确。

工程准入：原参数初始化一致、初始化映射一致、真实梯度/更新、optimizer覆盖、奇数尺寸、严格保存重载、部署一致性。历史synthetic检查见../server-toolkit-evidence.md，不等于真实数据实验；最终冻结实现需核对应源码。

性能主对照B0与A1使用相同DF2K、RGB L1、完整1M更新LR时间轴、effective batch64、FP32、量化/Y通道/crop4、无自集成。先5k/20k检查学习状态，100k筛选；短筛不是最终增益证明。公共测试集只监测，holdout用于选择；是否与训练数据有重叠需先核。不得从论文同时加入FFT loss来混淆模块收益。
