# 失稳与工程问题记录

以下记录来自本对话中的服务器报告，×3相关原始文件可由服务器收集器补充。原因分析区分实测现象和待验证解释。

## ×2在199K附近的失稳

原轨迹在199458更新的第三个micro-batch出现L1=1.139984，大于保护阈值1。异常前199455–199457的整步L1连续升高。最近完整断点为199K。独立重放457次完整更新，损失差值全部为0。

bound8实际执行，但SG6门控乘积在压缩前大幅放大，部分层有大量特征饱和。UCAN写回能进一步放大主特征。单独补UCAN/窗口写回约束，对已经失稳的冻结现场只改善约2%，未用作正式修复。

固定批次在199454更新前后L1由0.01348升至0.12915，回退输入卷积或卷积主干参数能明显缓解。199457时重建部分回退影响较大。Adam在当前梯度回落时仍有历史状态驱动的参数更新。上述证据支持更新与特征放大共同参与，最初触发源尚未完全定位。

全局梯度裁剪1.0的重放在199455仍触发保护。裁剪0.1从199K完成200K，再完成后续1M轨迹。阈值0.1是经过这段验证的可用设置，没有完成全阈值最优性证明。

## ×3需要独立记录

×3原轨迹在171212更新触发损失保护，恢复自171K并加入裁剪0.1。295K后仍发生严重失稳，296K普通DIV2K_valid由295K的32.46529下降到30.71017，原300K为31.34155。295453更新的裁剪前全局梯度范数约19928.95。

从同一295K完整断点、保留clip0.1并把学习率提前从1e-4改为5e-5的恢复试验成功完成300K。固定300K普通DIV2K_valid为32.48121，5K中裁剪32次。这个恢复试验改变了×3学习率时间线，不能写成原400K才减半的轨迹。

用户另行授权clip0.5、原学习率1e-4的295K→300K对照。此归档目前没有收到其最终结果，状态标为待补。不能把×2的clip结果视为×3阈值结论。

## 日志与存储

×3历史loss_steps在127201–127213存在缺口。恢复工具保留并记录缺口，严格核对断点前最近1000条损失，不补造历史记录。

work为NFS存储。曾在训练验收后出现shell Input/output error，随后完整断点可读，小文件fsync及读回成功。底层I/O原因尚未确认。

×2的1M训练完成后，自动归还脚本在sync -f工作目录时收到Input/output error，尚未调用归还命令。训练完成、断点校验与关机成功是三个不同状态。后续建议采用关键文件落盘与读回校验，实例归还按用户当次授权执行。

部分诊断早期版本存在观测缺陷。Adam.step包装层使初次调用栈定位失效，修正版沿栈找到训练器后取得有效记录。SPAB多返回项曾混在同一模块名下，后续区分main/first_feature/gate并核验约束实际调用。失效观测不能作为机制证据。
